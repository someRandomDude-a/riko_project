# Desktop model setup

Open **Settings → Desktop model**. Import/use a VRM first so the renderer can discover the skeleton. Original VRM files, skin weights, spring definitions and colliders are preserved.

Use **Search settings** (or **Ctrl+K** while Settings is open) to find runtime fields, graphics controls, model physics and individual bones. Choose a result to jump to its category/control, or expand **Edit here** to adjust it without leaving the menu. Local preferences apply immediately; runtime edits use the same validated draft and **Save runtime settings** flow as the main page. Search never matches saved credential values. Complex tools such as animation imports and interaction connections open their dedicated section.

- **Interaction connections:** bone → click/hold/release/ragdoll/recover → procedural pose or imported VRMA/pose clip, plus expression. Select a saved connection to edit it. Import clips in the animation library above. Hit-volume outlines and bone filters are independent of picking. Hovered/held bone labels appear only while this settings category is open.
- **Physics/calibration:** select any discovered bone, including hair/accessory and humanoid bones. Enable rotational secondary motion and tune blend, frequency, damping and angular lag. Imported spring joints additionally expose stiffness, drag, gravity and collider radius overrides. Reset restores imported settings.
- **T-pose:** preview pauses local animation playback; local metre offsets are applied each frame without accumulating. Offsets do not rewrite the mesh's bind weights. Preview is not an animation export tool.
- **Pickup/ragdoll:** the held bone anchors articulated angular dynamics and body pendulum motion. Thresholds measure travel from the grab point (pixels) or instantaneous speed (pixels/second). Crossing either threshold softens joints until release; release fires recovery and blends physics back out. Tune gravity, damping, body follow, inertia, angular limits and recovery duration. This is a bounded angular approximation, **not a rigid-body engine with ground/self collision**. Swinging automatically reframes the camera to reduce clipping.
- **Lighting/effects:** up to eight point/directional lights plus hemisphere lighting. JSON presets have `format: "riko-avatar-effects"`, `version: 1`, `lighting` and `effect`. Export creates an example. GLSL files must define `vec4 avatarEffect(vec4 color, vec2 uv, float time)`; these are alpha-preserving screen-space color effects, not replacement skeletal shaders. Imports never enable GLSL automatically. Files are capped at 16 KiB; loops and includes are disallowed. This does not sandbox GPU cost: only enable trusted shaders. Compile failures fall back to normal rendering for that session.

Runtime overrides are stored locally per model path and skeleton signature. No weight-painting, rig creation, file modification or VRM conversion is performed.

## Mouse interaction

Press/release below the configurable travel threshold is a click: it does not start body physics or send a hold trigger. Hover, delayed hover and leave have independent animation, expression and color-effect connections. Delayed hover is measured per bone and fires once per visit.

The mouse sphere has configurable radius, front depth, force, drag spring, follow frequency/damping, click Z-bounce amplitude/duration and joint limits. It interacts with imported springs and secondary-motion-enabled bones. Local dragging chooses one nearest endpoint once. A joint head is driven by its upstream eligible owner, while fixed rig roots stay fixed. Local spring dragging does not move the avatar window or enter body pickup. This is a torque layer over imported springs, not a replacement collider/rig engine.

**Spring bone dragging → Spring drag strength** (0–100, default 25) is separate from sphere pushing; dragging remains available when the force sphere is disabled. Endpoint selection uses the initial click ray, not the smoothed sphere, and includes VRM virtual tails. A camera-facing plane through the grabbed endpoint preserves its starting depth and grab offset. The pull is angular and normalized for segment length so short hair/accessory joints remain responsive; higher strength increases follow-through, while 0 disables the pull. Existing angular limits still apply. A fixed root head cannot move; grab its tail or a movable downstream endpoint instead.

Every imported spring joint has a refitted capsule selection volume, including springs mapped to humanoid bones and terminal joints with virtual tails. **Spring selection radius** widens these targets without changing collision physics. **Interaction connections → Show hit-volume outlines** displays the actual pick volumes; the outline filter includes hair/accessory springs and does not disable picking.

**Eye tracking & pupil convergence** follows the mouse sphere with smoothed, bounded eye rotation. Near targets increase binocular convergence and apparent pupil spacing without translating the eyes or changing anatomical IPD. Mouse depth is synthetic, controlled by sphere depth and minimum target distance. Bone-based VRMs support independent eyes; expression-only VRMs support shared gaze only. T-pose and disabled mouse tracking suspend the procedural gaze layer.

Body pickup uses a position-only anchor: gravity torque and movement inertia determine orientation, rather than forcing a target rotation. Graphics controls live in **Settings → Graphics**, with canvas anti-aliasing, effect-pass MSAA, GPU-capped anisotropic filtering and render pixel ratio.
